#### (h) BitTorrent con web seed sobre SourceForge, medido sin subir nada (la misma tarde, a pregunta de Jorge)

**La pregunta**, después de leer las opciones de (a): *«¿no se puede hacer
algo con BitTorrent? me suena web seed»*, y luego *«creo que lo voy a hacer con
SourceForge… no sé si se puede usar web seed entonces»*. La respuesta corta
está medida abajo: **sí**. La larga: una web seed (BEP 19, `url-list`) es una
URL HTTP que sirve el fichero entero y que el cliente usa como semilla cuando
no hay pares; es una **capa de reparto encima de un alojamiento**, no un
alojamiento. Con GitHub en trozos no encaja (la web seed mapea un fichero a
una URL; no sabe pegar trozos); con SourceForge, archive.org o R2, sí.

**Medido de sólo lectura contra un fichero público de otro proyecto**
(`sevenzip`, `7z2409-linux-arm64.tar.xz`, 1 324 144 bytes), sin cuenta y sin
subir nada:

```
== la URL canonica, HEAD siguiendo redirecciones
HTTP/2 302   location: https://ixpeering.dl.sourceforge.net/project/sevenzip/…/7z2409-linux-arm64.tar.xz?viasf=1&fid=c2bad612…&e=1788104…
HTTP/1.1 200 OK   Content-Length: 1324144   Accept-Ranges: bytes
== Range 0-1023 sobre la URL canonica                       HTTP 206  1024 bytes
== el espejo SIN el token                                   301 -> https://downloads.sourceforge.net/project/sevenzip/…   (y con ?viasf=1 solo, igual)
== master.dl.sourceforge.net                                301 -> http://downloads.sourceforge.net/…?viasf=1
== huellas que publica SourceForge (RSS del directorio)     media:hash algo="md5" — y solo md5 (2 de 2 ficheros)
```

Es decir: **la URL estable es la canónica** (`downloads.sourceforge.net/project/…`);
los espejos llevan un token que caduca y sin él devuelven al canónico, así que
la web seed tiene que ser la canónica y el cliente tiene que seguir el `302`.
Y **lo que dije en (a) de que SourceForge «enseña el SHA-256» no está
demostrado**: su RSS publica `md5` y nada más; la página del fichero la pinta
JavaScript y no se leyó. El `SHA256SUMS` va al lado, como estaba previsto.

**El `.torrent`, reproducible**: un guion de sesión de 20 líneas
(`hacer-torrent.py`, bencode a mano, sin dependencias) que escribe un torrent de
un fichero, piezas de 1 MiB, **sin fecha y sin tracker**, con `url-list` a la
URL canónica. Dos pasadas, **el mismo fichero byte a byte**, *infohash*
`796b3da9…`. **Y la bajada, con `aria2c` 1.37.0 (`brew install aria2`, la
única herramienta de torrent que había que poner) sin DHT, sin DHT6, sin LPD,
sin PEX y sin tracker: la web seed es la única fuente posible:**

```
[#957fe8 848KiB/1.2MiB(65%) CN:1 SD:0 DL:548KiB]          (CN:1 = una conexion, la HTTP; SD:0 = cero semillas)
Download complete   400KiB/s   OK
sha256 de lo bajado = sha256 de lo bajado por curl   (fbe33169…)
```

**Los dos controles, y dan sus dos respuestas:**

```
== CONTROL 1: la web seed CORTADA (http://127.0.0.1:1/), sin pares, --bt-stop-timeout=15
(ERR):error occurred.     7z.tar.xz  0 bytes
== CONTROL 2: el sha1 de la pieza 2 cambiado en UN byte (byte 141 del .torrent)
ERROR Download aborted … Exception: [DownloadCommand.cc:399] errorCode=1 Invalid checksum index=1
(ERR)   7z.tar.xz  1048576 bytes (la pieza 1, y ahi se para)
```

**Lo que esto dice y lo que no.** Con SourceForge como alojamiento **se puede
publicar un `.torrent` por ISO con web seed a la URL canónica**, y un cliente
lo baja entero sin que nadie siembre; la integridad de las piezas es una
comprobación más, además del `SHA256SUMS`. Lo medido es con `aria2c`, que
sigue el `302`; **qBittorrent y Transmission, que son lo que usaría un
desconocido, no se han medido** —libtorrent y curl también siguen
redirecciones, pero eso es deducido y va como `[OMIT]`—. Y lo que no cambia:
el fichero entero tiene que vivir en SourceForge (o donde sea) igualmente; el
torrent no sustituye la URL ni la huella al lado. Cuando el proyecto de
SourceForge exista —eso es una cuenta y es de Jorge—, el guion de sesión pasa
a `imagen/` como `make torrent`, con la URL canónica del proyecto, y la orden
de subida (`rsync` a `frs.sourceforge.net`) se escribe y se mide entonces.
